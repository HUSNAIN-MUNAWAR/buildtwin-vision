# BuildTwin runtime evidence

These artifacts were generated by the existing `backend.app.vision.video_reader.process_video` path over the committed `sample_data/videos/level1_progress.mp4` demo video:

```powershell
$env:PYTHONPATH = "backend"
py -3.12 scripts/generate_runtime_evidence.py
```

The run decodes the MP4, samples every 12th frame, computes Canny edge density, writes the same overlay frames used by the backend, encodes them into an annotated MP4, and records the measured trace. The source is synthetic demo input and is labeled as such in the summary.

- `buildtwin-progress-runtime.mp4`: sampled annotated runtime animation.
- `buildtwin-progress-runtime-poster.jpg`: decoded poster frame from that animation.
- `buildtwin-progress-edge-trace.csv`: frame/timestamp/edge-density trace.
- `buildtwin-progress-runtime-summary.json`: source hash, runtime measurements, artifact hashes, and claim boundary.

This is evidence that the local media-processing path executes. It is not evidence of a trained construction model, defect detector, BIM registration, or field accuracy.
